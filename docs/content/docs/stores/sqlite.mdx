---
title: SQLite Store
description: Lightweight SQLite store for development, testing, and single-node deployments.
---

The `store/sqlite` package implements Nexus's `store.Store` interface on [Grove](https://github.com/xraph/grove) with its SQLite driver. It needs no database server, which makes it a good fit for development, integration tests and single-node deployments.

## Usage

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    "github.com/xraph/nexus/store/sqlite"
)

drv := sqlitedriver.New()
if err := drv.Open(ctx, "nexus.db"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := sqlite.New(db)
if err := s.Migrate(); err != nil {
    log.Fatal(err)
}

gw := nexus.New(
    nexus.WithDatabase(s),
)
```

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | Grove with `sqlitedriver` |
| Migrations | `sqlite.Migrations`, run by Grove's orchestrator in `Migrate()` |
| Tables | `tenants`, `api_keys`, `usage_records` (no `nexus_` prefix) |
| Usage metadata | `usage_records.metadata`, JSON text, `'{}'` when the request set none |
| Close | `s.Close()` closes the `grove.DB`, and `gw.Shutdown` calls it |

## Usage metadata

The `usage_metadata` migration (version `20261024000001`, group `nexus`) adds a `metadata` text column to `usage_records`. A metadata filter matches each pair with `json_extract`. The column has no index, so a filter reads every row in the other filters' range. That's fine at SQLite's scale, but use PostgreSQL if you filter large usage tables by metadata.

## When to use

- Development and local testing without external dependencies.
- Single-process or embedded deployments.
- CI pipelines where running PostgreSQL is impractical. The store's own tests always run.
