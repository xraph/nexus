---
title: MongoDB Store
description: MongoDB store for document-oriented deployments.
---

The `store/mongo` package implements Nexus's `store.Store` interface on [Grove](https://github.com/xraph/grove) with its MongoDB driver. It stores tenants, API keys and usage records as documents, which suits deployments that already run MongoDB.

## Usage

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/mongodriver"
    "github.com/xraph/nexus/store/mongo"
)

drv := mongodriver.New()
// The database name comes from the URI path, or from mongodriver.WithDatabase.
if err := drv.Open(ctx, "mongodb://localhost:27017/nexus"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := mongo.New(db)
if err := s.Migrate(); err != nil {
    log.Fatal(err)
}

gw := nexus.New(
    nexus.WithDatabase(s),
)
```

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | Grove with `mongodriver` |
| `Migrate()` | Creates the indexes and normalizes usage documents written before exact money |
| Collections | `nexus_tenants`, `nexus_api_keys`, `nexus_usage_records` |
| Money | Costs are stored as `Decimal128` |
| Usage metadata | A `metadata` subdocument on each usage record, with a wildcard index on `metadata.$**` |
| Close | `s.Close()` closes the `grove.DB`, and `gw.Shutdown` calls it |

## Grove Migrations

The package also exports `mongo.Migrations`, a Grove `migrate.Group` named `nexus` that creates the same indexes. Register it with Grove's migration orchestrator if you want Nexus's indexes tracked alongside the rest of your app's migrations. `s.Migrate()` doesn't use it: it creates the indexes directly.

## Usage metadata

Each usage record keeps the request's `Metadata` map in a `metadata` subdocument, and a filter matches `metadata.<key>` for each pair you ask for. The wildcard index `metadata.$**` covers any key. `s.Migrate()` creates it with the other indexes, and `mongo.Migrations` has it as the `usage_metadata` migration (version `20261024000001`). Building it on a large collection takes a while. You can create it ahead of the upgrade (`{"metadata.$**": 1}`, named `metadata.$**_1`), and the migration finds it in place.

Records written before this release have no `metadata` field and read back with an empty map.

## When to use

- Deployments where MongoDB is already the primary data store.
- Teams already running MongoDB in their infrastructure.

The store's tests only run when `NEXUS_TEST_MONGO_URI` is set, and CI doesn't set it.
