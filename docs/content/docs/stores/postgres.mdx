The `store/postgres` package implements Nexus's `store.Store` interface on [Grove](https://github.com/xraph/grove) with its PostgreSQL driver. It's the store to use when several replicas share one database.

## Setup

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    "github.com/xraph/nexus/store/postgres"
)

drv := pgdriver.New()
if err := drv.Open(ctx, "postgres://user:pass@localhost:5432/nexus?sslmode=disable"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := postgres.New(db)
if err := s.Migrate(); err != nil {
    log.Fatal(err)
}

gw := nexus.New(
    nexus.WithDatabase(s),
)
```

In a Forge app you don't need any of this: the [Forge extension](/docs/guides/forge-extension#grove-database-integration) builds the store from the app's `grove.DB` and migrates it on start.

## Migrations

Call `s.Migrate()` before first use. It runs the package's `postgres.Migrations` group through Grove's migration orchestrator, which tracks what has already run, so it's safe on every startup.

## Schema

Tables are prefixed with `nexus_`. Quota, config and metadata are `jsonb` columns.

- `nexus_tenants`: id, name, slug, status, quota, config, metadata, created_at, updated_at
- `nexus_api_keys`: id, tenant_id, name, prefix, hash, scopes, status, expires_at, last_used_at, metadata, created_at
- `nexus_usage_records`: id, tenant_id, key_id, request_id, provider, model, prompt_tokens, completion_tokens, total_tokens, cost_usd, pricing_status, outcome, blocked_by, refusal_code, latency_ns, cached, status_code, created_at

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | Grove with `pgdriver` |
| Migrations | `postgres.Migrations`, run by Grove's orchestrator |
| Close | `s.Close()` closes the `grove.DB`, and `gw.Shutdown` calls it |

## When to use

- Production deployments with more than one replica. The monthly budget and daily counts come from the usage store, so every replica sees the same totals.
- When you already run PostgreSQL.

The store's tests only run when `NEXUS_TEST_POSTGRES_DSN` is set, and CI doesn't set it.
