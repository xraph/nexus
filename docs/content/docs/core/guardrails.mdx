---
title: Guardrails
description: Check prompts and responses for PII, prompt injection, blocked words and your own regex rules.
---

Guardrails inspect, and can rewrite, a request's messages before they reach a provider, and a response's messages, streamed or not, before they reach the client. Add them with `nexus.WithGuard`, one call per guard. They run in the order you add them.

```go
import (
    "github.com/xraph/nexus/guard"
    "github.com/xraph/nexus/guard/guards"
)

gw := nexus.New(
    nexus.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),
    nexus.WithGuard(guards.NewPII(guard.ActionRedact)),
    nexus.WithGuard(guards.NewInjection()),
)
```

## Guard Interface

```go
type Guard interface {
    Name() string
    Phase() Phase // guard.PhaseInput, guard.PhaseOutput or guard.PhaseBoth
    Check(ctx context.Context, input *CheckInput) (*CheckResult, error)
}
```

`CheckInput` carries the `Messages`, the `TenantID` and a copy of the request's `Metadata`, so a guard can read it but can't change the request. `CheckResult` says whether the content is `Blocked`, which `Action` applies, a `Reason`, and, when `Modified` is true, the rewritten `Messages`.

## Built-in Guards

All of them look only at messages whose content is a plain string. Multi-part content (text plus images) is skipped.

### PII

```go
guards.NewPII(guard.ActionRedact) // or guard.ActionBlock, guard.ActionWarn
```

Finds email addresses, US-style phone numbers, social security numbers and card numbers. With `ActionRedact` it replaces them with `[EMAIL_REDACTED]`, `[PHONE_REDACTED]`, `[SSN_REDACTED]` and `[CC_REDACTED]`. Runs on input and output.

### Prompt Injection

```go
guards.NewInjection()
```

Blocks input that matches a fixed list of injection phrases ("ignore previous instructions" and the like). Runs on input only.

### Content Filter

```go
guards.NewContentFilter(guard.ActionBlock, "forbidden phrase", "another one")
```

Case-insensitive substring match against your blocklist. Runs on input and output.

### Regex Rules

```go
g := guards.NewRegex("secrets", guard.PhaseInput).
    AddRule("api_key", `(?i)api[_-]?key`, guard.ActionBlock, "API keys are not allowed in prompts").
    AddRedactRule("aws_key", `AKIA[0-9A-Z]{16}`, "[AWS_KEY]")

nexus.WithGuard(g)
```

`AddRule` takes a name, a pattern, an action and a reason. `AddRedactRule` takes a name, a pattern and the replacement text. Patterns are compiled with `regexp.MustCompile`, so a bad pattern panics when you build the guard.

## Actions

| Action | What happens |
|--------|----------|
| `guard.ActionAllow` | The content passes unchanged |
| `guard.ActionBlock` | The request fails with a `*guard.BlockedError`, which the HTTP edge returns as 400 `content_blocked` |
| `guard.ActionRedact` | The matched text is replaced and the request goes on |
| `guard.ActionWarn` | The content passes unchanged. Nothing is logged: the guard service only acts on blocks and rewrites |

The first guard that blocks stops the check. Rewrites from earlier guards carry through to later ones.

An output-phase block happens after the provider has answered and charged for it, so the `BlockedError` carries the `Usage`, `Model` and `Provider` of the refused response, and the usage stage records it as blocked.

## Streaming

Output guards check streamed replies too. You don't have to wire anything: when any guard runs on output, the gateway adds the stream guardrail stage at priority 155, and by default it holds the reply back until the guards have passed it. You pick another strategy with `nexus.WithStreamGuardStrategy`.

| Strategy | What the client gets |
|----------|----------|
| `guard.StrategyBuffer` (default) | Nothing until the reply has ended and passed. A block ends the stream with `*guard.BlockedError` before any chunk goes out. A redaction takes effect: the client gets a rebuilt stream with the rewritten text, the tool calls, the finish reason and the usage. The rebuilt stream has no reasoning, citations, audio or images, even where the original had them |
| `guard.StrategyPassthrough` | Chunks as the provider sends them. The guards run when the provider ends the stream, and a block replaces `io.EOF` with `*guard.BlockedError`. Text that already went out can't be redacted, so the stream ends normally and the gateway logs a warning |
| `guard.StrategyChunkwise` | Each chunk once your stream guards have passed it, then the same check at the end as passthrough |

Pick passthrough for token-by-token chat, where a reply held back until it ends feels broken and your guards only block (a blocklist, say). The client sees text before the verdict, so a block can only stop the rest of the reply and tell the client. If you act on tool calls, run them only after the stream ends without an error, since a blocked reply never ends with `io.EOF`. When a redacting guard has to take effect, or when the client must never see blocked text, stay on buffer.

The gateway decides whether to add the stream stage when `Initialize` runs, from the guards registered by then. An output guard you add later through `gw.Guard().Register` checks non-streamed replies but never reaches a stream, unless another output guard or a `WithStreamGuard` already put the stage in. Register your guards with `WithGuard` before `Initialize`.

If you build the stage yourself with `middlewares.NewStreamGuardrail(guards, strategy)`, an empty strategy means buffer. Don't also add it with `WithMiddleware` on a gateway that adds its own, or every stream gets checked twice.

A `StreamGuard` is a `Guard` with a `CheckChunk` method, and you add one with `nexus.WithStreamGuard`. It checks every chunk under buffer and chunkwise. Passthrough doesn't run it, and none of the built-in guards implement it.

Whatever the strategy, a reply a guard blocked or rewrote never carries its native content (the provider's own copy of the reply, with the original text and thinking).
