---
title: Tenant Credentials
description: Serve each tenant on its own provider key, and on a compatible server its own base URL, with the configured key as the fallback.
---

One gateway can serve every tenant on that tenant's own provider key. You give it a credential provider, and before each provider call the gateway asks it which key to use. When a tenant has none, the provider's configured key answers instead.

```go
gw := nexus.New(
    nexus.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),       // the fallback key
    nexus.WithProvider(anthropic.New(os.Getenv("ANTHROPIC_API_KEY"))),
    nexus.WithCredentialProvider(vaultKeys{store: secrets}),
)
```

`WithCredentialProvider` takes any `provider.CredentialProvider`:

```go
type CredentialProvider interface {
    GetCredential(ctx context.Context, providerName string) (string, error)
}
```

## Writing a resolver

The gateway calls your provider after it has routed the request, once per attempt, so a retry asks again. `pipeline.TenantID(ctx)` holds the request's nexus tenant id (a TypeID such as `tenant_...`), or `""` for an unattributed request. `providerName` is the registered name of the provider the request was routed to.

```go
type vaultKeys struct{ store SecretStore }

func (v vaultKeys) GetCredential(ctx context.Context, providerName string) (string, error) {
    tenantID := pipeline.TenantID(ctx)
    if tenantID == "" {
        return "", provider.ErrCredentialNotFound // unattributed: use the configured key
    }
    key, err := v.store.Get(ctx, tenantID, providerName)
    if errors.Is(err, ErrNoSuchSecret) {
        return "", provider.ErrCredentialNotFound // this tenant brings no key
    }
    if err != nil {
        return "", fmt.Errorf("reading the key for %s: %w", providerName, err)
    }
    return key, nil
}
```

What you return decides what happens next:

| You return | The gateway |
|------------|-------------|
| A key | Sends the request with that key |
| `provider.ErrCredentialNotFound`, wrapped or not, or an empty key | Sends the request with the provider's configured key |
| Any other error | Refuses the request with `nexus.ErrCredentialUnavailable` (503 `unavailable`) and calls no provider |

That last row matters. If your secret store is down, the request fails. It does not quietly fall back to the operator's key, because a tenant that brings its own key expects to pay for its own traffic. The refusal isn't retried, and the usage stage records it as refused at $0. Keep keys out of your error text: the gateway wraps your error in the refusal.

`nexus.ErrCredentialNotFound` is the same value as `provider.ErrCredentialNotFound`, so use whichever import you already have. `provider.StaticCredential` and `provider.EnvCredential` return it too.

## Choosing the base URL

A provider that implements `provider.CredentialResolver` can choose the endpoint as well as the key:

```go
type CredentialResolver interface {
    ResolveCredential(ctx context.Context, providerName string) (Credential, error)
}

type Credential struct {
    APIKey  string // never logged or put in an error
    BaseURL string // "" keeps the provider's configured base URL
}
```

When the value you pass to `WithCredentialProvider` implements it, the gateway calls `ResolveCredential` and never `GetCredential`. The rules for errors are the same, and an empty `Credential` counts as not found.

A credential with a `BaseURL` brings its own key. The provider sends `APIKey`, even an empty one, to that URL, and never its configured key, so the operator's key can't leak to a host a tenant picked. An empty key on an OpenAI or opencompat request goes out with no `Authorization` header at all. On Anthropic it fails with `provider.ErrMissingAPIKey` before anything is sent.

This is how you serve "bring your own OpenAI-compatible server". Register one opencompat provider with no base URL and no key, and let the resolver supply both per tenant:

```go
nexus.WithProvider(opencompat.New("custom", "", "")),
nexus.WithCredentialProvider(workspaceEndpoints{}),
```

A request routed to `custom` whose tenant has no credential fails with `provider.ErrMissingBaseURL` before any network call, and it isn't retried. See [OpenAI-Compatible](/docs/providers/opencompat#a-base-url-per-tenant).

### Validate the base URL yourself

Nexus trusts the URL your resolver returns and sends the request body, and the tenant's key, there. If tenants choose that URL, check it on your side before you return it, both when you save it and when you resolve it:

- allow only `https` (or the schemes you actually mean to support);
- refuse private, loopback, link-local and cloud metadata addresses;
- guard against DNS rebinding by checking the address the name resolves to when you dial, not only when the URL was saved.

Skip this and a tenant can point the gateway at `http://169.254.169.254/` or a service inside your network.

## Which providers take a credential

Three providers apply a per-request credential: `anthropic`, `openai` and `opencompat`. They implement `provider.CredentialAware` and answer true.

```go
type CredentialAware interface{ AcceptsCredentials() bool }
```

If your resolver returns a credential for any other provider, the gateway refuses the request with `ErrCredentialUnavailable`. It won't serve the tenant on the operator's key in that case either. Return `ErrCredentialNotFound` for providers your tenants cannot bring keys to.

With a tenant key, the OpenAI provider also drops the configured `OpenAI-Organization` header, since a tenant's key does not belong to the operator's organization.

Keys never show up in logs, usage records or errors. `Credential` prints as `Credential{APIKey: set, BaseURL: ...}` under every `fmt` verb, and the OpenAI and Anthropic providers cut the key out of an error body that echoes it back.

## What does not get a credential

The credential provider is part of the default pipeline's provider call stage. Two things skip it:

- A pipeline you set with `WithPipeline`. Add `middlewares.NewProviderCall(...).WithCredentialProvider(cp)` to your own provider call stage.
- The `fallback` service, which calls providers outside the pipeline.

The gateway also clears any credential already on the caller's context before the provider call, so `provider.WithCredential` on a context you pass to `Engine` has no effect. Only the credential the gateway resolved for the routed provider reaches it.
