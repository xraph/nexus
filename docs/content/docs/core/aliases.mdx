---
title: Model Aliases
description: Map virtual model names to concrete models, with weighted targets and per-tenant overrides.
---

Model aliases let clients ask for logical names like `"fast"` or `"smart"` instead of provider model IDs, so you can change the model behind a name without touching clients.

## Creating Aliases

```go
import "github.com/xraph/nexus/model"

gw := nexus.New(
    nexus.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),
    nexus.WithAlias("fast", model.AliasTarget{
        Provider: "openai",
        Model:    "gpt-4o-mini",
    }),
    nexus.WithAlias("smart", model.AliasTarget{
        Provider: "openai",
        Model:    "gpt-4o",
    }),
)
```

A client that sends `"model": "fast"` gets its request rewritten to `gpt-4o-mini`. A model name that isn't an alias passes through unchanged.

The alias stage rewrites the model, and the target's `Provider` decides where the request goes: an alias for an Anthropic model reaches Anthropic even with OpenAI registered first. A target whose provider isn't registered refuses the request with `ErrUnknownProvider` (400). A target with no `Provider` leaves the choice to the model's catalog listing and then the strategy. See [Routing](/docs/core/routing#how-a-provider-is-picked).

## Weighted Targets

Give an alias several targets and each request picks one at random by weight. A target with no weight (or zero) counts as 1:

```go
nexus.WithAlias("balanced",
    model.AliasTarget{Provider: "openai", Model: "gpt-4o-mini", Weight: 0.7},
    model.AliasTarget{Provider: "openai", Model: "gpt-4o", Weight: 0.3},
)
```

The targets aren't a fallback chain. If the chosen target fails, the retry stage retries that same model.

## Per-Tenant Overrides

Different tenants can resolve the same alias to different models:

```go
nexus.WithTenantAlias(premiumTenantID, "fast",
    model.AliasTarget{Provider: "openai", Model: "gpt-4o"},
)
```

The first argument is the tenant's ID (`t.ID.String()`), not its slug. When that tenant asks for `"fast"` it gets `gpt-4o`, and everyone else gets the alias's default targets. If no `"fast"` alias exists yet, `WithTenantAlias` creates one whose default targets are the same as the override, so register the default with `WithAlias` first.

A tenant can also have a default model in its config (`tenant.Config.DefaultModel`). The access stage fills it in when a request names no model, before alias resolution, so the default may itself be an alias.

## Alias Resolution

Alias resolution is a pipeline stage at priority 250, after guardrails and transforms and before the tenant's model allow and block lists (260) and the cache (280). The stage is only in the pipeline when you register at least one alias. The model policy checks both the name the client asked for and the model the alias produced. `gw.Aliases()` lists what's registered.
