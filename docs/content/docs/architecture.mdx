## Overview

Nexus is organized as a set of composable Go packages. The `Gateway` is the root struct that wires everything together.

```
┌─────────────────────────────────────────────────┐
│                    Gateway                       │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐  │
│  │ Providers │  │  Router  │  │   Pipeline   │  │
│  │ Registry  │  │ Strategy │  │  Middleware   │  │
│  └──────────┘  └──────────┘  └──────────────┘  │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐  │
│  │  Cache   │  │  Guards  │  │  Transforms  │  │
│  │ Service  │  │ Service  │  │   Registry   │  │
```

## Request Flow

Every request flows through the pipeline middleware chain, sorted by priority:

1. **Request ID** (5) — Assign the request id
2. **Tracing** (10) — OpenTelemetry span creation
3. **Usage** (15) — Record, price and attribute every request
4. **Timeout** (20) — Request deadline enforcement
5. **Identity** (30) — Tenant and key ids, so the cache and usage agree on who asked
6. **Stream Lifecycle** (60) — Extension hooks for streams
7. **Guardrails** (150) — Input content validation
8. **Transforms** (200) — Input modifications (system prompt, RAG)
9. **Alias Resolution** (250) — Virtual model → concrete provider/model
10. **Cache** (280) — Check for cached response
11. **Retry** (340) — Retry logic with backoff
12. **Custom middleware** — Yours, by priority
13. **Provider Call** — Route and call the selected provider. Always last.

The usage stage sits above everything that can refuse, replay or retry a request, so one request produces one usage record whatever happens below it. The gateway sets no response headers.

## Pipeline Middleware

All middleware implements:

```go
type Middleware interface {
    Name() string
    Priority() int
    Process(ctx context.Context, req *Request, next NextFunc) (*provider.CompletionResponse, error)
}
```

Lower priority numbers execute first. Custom middleware can be inserted at any priority level.

## Plugin System

Plugins implement lifecycle hooks as separate interfaces. The registry type-caches hooks at registration time for zero-overhead dispatch:

```go
type Extension interface {
    Name() string
}

// Opt in to specific events
type RequestReceived interface {
    OnRequestReceived(ctx context.Context, ...) error
}
```

15 hooks cover: request lifecycle, provider events, guardrail events, tenant/key management, and budget alerts.
