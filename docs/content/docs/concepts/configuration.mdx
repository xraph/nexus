## Functional Options

The primary way to configure Nexus is via functional options:

```go
gw := nexus.New(
    nexus.WithBasePath("/ai"),
    nexus.WithRateLimit(1000),
    nexus.WithTimeout(30 * time.Second),
    nexus.WithMaxRetries(3),
)
```

## Config Struct

The `Config` struct holds all gateway settings:

```go
type Config struct {
    BasePath          string
    GlobalRateLimit   int
    DefaultTimeout    time.Duration
    DefaultMaxRetries int
    EnableUsage       bool
    EnableCache       bool
    RequireAPIKey     bool
    LogLevel          string
}
```

`DefaultConfig()` returns sensible defaults. `RequireAPIKey` is true by default, which means the `api` and `proxy` routes refuse a request without a valid gateway key. Set it to false for local work and the `/v1` routes open up. The `/admin` routes stay closed. See [Authentication](/docs/api-reference/http-api#authentication).

`EnableUsage` is true by default. Turn it off and the gateway writes no usage rows, which also makes a tenant's `DailyRequests` and `MonthlyBudgetUSD` limits inert, since both are counted from those rows. RPM, TPM and the token cap still apply.

`GlobalRateLimit` is requests per minute across the whole gateway, every tenant and every unattributed request included. Zero means no limit. It is enforced: the quota stage charges one request against it before it looks at the tenant's own limits, and a request over it gets a 429 `rate_limited`.

## Available Options

| Option | Description |
|--------|-------------|
| `WithConfig(cfg)` | Set the full config struct |
| `WithDatabase(store)` | Set the persistence store |
| `WithAuth(provider)` | Set the auth provider |
| `WithProvider(p)` | Register an LLM provider |
| `WithRouter(strategy)` | Set the routing strategy |
| `WithCache(cache)` | Enable response caching |
| `WithGuard(guard)` | Add a guardrail |
| `WithMiddleware(m)` | Add custom pipeline middleware |
| `WithExtension(ext)` | Register a lifecycle plugin |
| `WithAlias(name, targets...)` | Register a model alias |
| `WithLogger(logger)` | Set a custom logger |
| `WithBasePath(path)` | Set the HTTP base path |
| `WithRateLimit(rpm)` | Set global rate limit |
| `WithRequireAPIKey(on)` | Require a gateway key on the `/v1` routes (default true) |
| `WithLimiter(l)` | Set the RPM and TPM limiter (default: in-process memory) |
| `WithTracer(tracer)` | Set the request tracer |
| `WithTransforms(registry)` | Set input/output transforms |
| `WithTimeout(duration)` | Set default request timeout |
| `WithMaxRetries(n)` | Set default max retries |
| `WithTenantAlias(tid, name, targets...)` | Per-tenant alias override |

## Sharing rate limit windows between replicas

The default limiter keeps its windows in the process, so each replica counts on its own: three replicas with a tenant RPM of 60 let that tenant make 180 requests a minute. If replicas should share one window, hand the gateway a Redis limiter:

```go
import (
    "github.com/redis/go-redis/v9"
    "github.com/xraph/nexus/ratelimit/redislimit"
)

client := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
gw := nexus.New(
    nexus.WithLimiter(redislimit.New(client)),
)
```

Windows are fixed and aligned to the clock of the replica that charges them, so keep replica clocks in sync. If Redis goes down the limiter fails open: requests go through, `gw.LimiterErrors()` counts each failure, and the gateway logs it. The monthly budget does not come from the limiter. It comes from the usage store, so every replica already shares it. The daily request cap uses both: the store count, which every replica shares, and a charge to a UTC-day window in the limiter, which makes it hard when requests arrive together. With the memory limiter that charge is per replica.

## File-based configuration (Forge extension)

When Nexus runs as a [Forge extension](/docs/guides/forge-extension), it can load configuration from the application's YAML config file. The extension checks two keys in order:

1. **`extensions.nexus`** -- namespaced under the Forge extensions convention (recommended)
2. **`nexus`** -- legacy top-level key

```yaml title="forge.yaml"
extensions:
  nexus:
    base_path: "/ai"
    default_timeout: "30s"
    default_max_retries: 2
    global_rate_limit: 1000
    require_api_key: true
    log_level: "info"
    enable_usage: true
    enable_cache: false
    grove_database: ""
    disable_routes: false
    disable_migrate: false
```

### Extension-specific fields

In addition to the gateway config fields, the extension config adds:

| Field | Type | Description | Default |
|-------|------|-------------|---------|
| `disable_routes` | `bool` | Disable automatic route registration | `false` |
| `disable_migrate` | `bool` | Disable automatic store migration | `false` |
| `grove_database` | `string` | Name of grove.DB to resolve from DI (empty = default DB) | `""` |

### Configuration precedence

When both file-based and programmatic options are provided, they are merged:

1. **YAML values** take precedence for string, duration, and integer fields.
2. **Programmatic boolean flags** (`DisableRoutes`, `DisableMigrate`, `EnableCache`) override when set to `true`.
3. Any remaining zero-valued fields are filled from `DefaultConfig()`.

If no file-based config is found and `RequireConfig` is not set, the extension falls back to programmatic options merged with defaults.
