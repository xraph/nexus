---
title: Forge Extension
description: Run Nexus as a forge.Extension that builds its store from Grove and registers the gateway in DI.
---

The `extension` package turns Nexus into a [Forge](https://github.com/xraph/forge) extension. It reads config under `extensions.nexus` (or `nexus`), builds a store from a `*grove.DB` in the container when it finds one, migrates it on start, creates the first admin key if you supply one, and registers `*nexus.Gateway` for the rest of your app.

## Setup

```go
package main

import (
    "log"
    "os"

    "github.com/xraph/forge"
    nexusext "github.com/xraph/nexus/extension"
    "github.com/xraph/nexus/providers/openai"
)

func main() {
    app := forge.NewApp(forge.AppConfig{
        Name:        "ai-gateway",
        Version:     "1.0.0",
        HTTPAddress: ":8080",
        Extensions: []forge.Extension{
            nexusext.New(
                nexusext.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),
            ),
        },
    })

    if err := app.Run(); err != nil {
        log.Fatal(err)
    }
}
```

`app.RegisterExtension(ext)` works too, before the app starts.

## Serving the API

The extension doesn't register any HTTP routes. It builds and starts the gateway, and that's all. To serve the OpenAI-compatible API or the admin API, mount a handler yourself once the gateway exists:

```go
import (
    "github.com/xraph/nexus/api"
    "github.com/xraph/nexus/proxy"
)

handler := proxy.New(gw.Engine()) // /v1 routes and /health
admin := api.New(gw).Handler()    // /v1 routes plus /admin
```

Both are plain `net/http` handlers. See the [HTTP API](/docs/api-reference/http-api) for the routes.

`base_path` and `disable_routes` (and `WithBasePath`, `WithDisableRoutes`) are accepted but do nothing in the extension today. `base_path` ends up in the gateway's config and its startup log line, and `disable_routes` has no routes to turn off.

## Getting the gateway

The extension registers `*nexus.Gateway` in the container during `Register`, but the gateway itself is created in `Start`. Resolve it after the app has started, or you get nil:

```go
gw, err := forge.Inject[*nexus.Gateway](app.Container())
```

`vessel.Inject[*nexus.Gateway](container)` does the same from another extension, and `ext.Gateway()` returns it straight from the extension (nil until `Start`).

## What it wires in

The extension resolves one thing from the container: a `*grove.DB`, for the store. It doesn't look for Chronicle, Shield, Relay or a metrics factory. To add audit, webhook or metrics hooks, pass them yourself:

```go
nexusext.New(
    nexusext.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),
    nexusext.WithGatewayOption(nexus.WithExtension(audit_hook.New(recorder))),
)
```

Authsome isn't wired in either. The gateway checks its own gateway keys, so an Authsome token sent to it gets a 401. See [Identity & Auth](/docs/concepts/identity).

The extension also implements the Forge dashboard contract (`RegisterContractContributor`), which serves tenants, keys, usage and gateway settings to a Forge dashboard host once the gateway has started.

## YAML configuration

The extension reads its settings from your app's config, under the first of these keys that exists:

1. `extensions.nexus` (namespaced, recommended)
2. `nexus` (legacy shorthand)

```yaml title="config.yaml"
extensions:
  nexus:
    default_timeout: 30s
    default_max_retries: 2
    global_rate_limit: 1000   # requests per minute, 0 means unlimited
    require_api_key: true
    log_level: info
    enable_usage: true
    enable_cache: false
    grove_database: ""        # a named grove.DB; empty uses the default one
    disable_migrate: false
    # bootstrap_admin_key: "nxs_..."   # or set NEXUS_BOOTSTRAP_ADMIN_KEY
```

### Configuration reference

| Field | YAML key | Type | Default | Description |
|-------|----------|------|---------|-------------|
| `DefaultTimeout` | `default_timeout` | `duration` | `30s` | Timeout for each request through the pipeline |
| `DefaultMaxRetries` | `default_max_retries` | `int` | `2` | Retries for a failed provider call |
| `GlobalRateLimit` | `global_rate_limit` | `int` | `0` | Requests per minute across the whole gateway, 0 for no limit |
| `RequireAPIKey` | `require_api_key` | `bool` | `true` | Require a gateway key on the `/v1` routes. The `/admin` routes always need an `admin` key. |
| `LogLevel` | `log_level` | `string` | `"info"` | Level for the gateway's log lines, written through the Forge logger |
| `EnableUsage` | `enable_usage` | `bool` | `true` | Record usage. Off means no usage rows, so the monthly budget can't apply |
| `EnableCache` | `enable_cache` | `bool` | `false` | Turn on an in-memory response cache (1000 entries, 10 minute TTL) |
| `GroveDatabase` | `grove_database` | `string` | `""` | Name of the `grove.DB` to resolve from DI; setting it turns Grove resolution on |
| `DisableMigrate` | `disable_migrate` | `bool` | `false` | Skip the store migration on start |
| `BootstrapAdminKey` | `bootstrap_admin_key` | `string` | `""` | The raw value of the first admin key: `nxs_` and 64 lowercase hex digits. When empty, the `NEXUS_BOOTSTRAP_ADMIN_KEY` environment variable is used. |
| `BasePath` | `base_path` | `string` | `"/nexus"` | Not used by the extension (no routes) |
| `DisableRoutes` | `disable_routes` | `bool` | `false` | Not used by the extension (no routes) |

A zero `default_timeout` or `default_max_retries` is treated as unset and gets the default, so you can't turn the timeout or retries off from config. Use `WithGatewayOption(nexus.WithMaxRetries(0))` in code for that.

### Merge behavior

When the config file has the key, file and code values are merged like this:

| Category | Precedence |
|----------|------------|
| Boolean flags (`disable_routes`, `disable_migrate`, `enable_cache`) | `true` from code wins |
| String fields (`base_path`, `log_level`, `grove_database`, `bootstrap_admin_key`) | The file wins; code fills a gap |
| Duration and int fields (`default_timeout`, `default_max_retries`, `global_rate_limit`) | The file wins; code fills a gap |
| Pointer fields (`enable_usage`, `require_api_key`) | The file wins; code fills a gap |

Any field still empty after that gets its value from `DefaultConfig()`. When the file has no key, the code config is merged with the defaults the same way.

Note that the file beats `WithConfig` here, the opposite of most Forge extensions. Gateway options you pass with `WithGatewayOption` are different: they're applied after the config, so `WithGatewayOption(nexus.WithTimeout(5*time.Second))` overrides `default_timeout`.

### The first admin key

The admin API always needs a key with the `admin` scope, and no route can make the first one. Set `bootstrap_admin_key`, or the `NEXUS_BOOTSTRAP_ADMIN_KEY` environment variable when the config leaves it empty, to a value you made (`nxs_` followed by the output of `openssl rand -hex 32`). On start, after the store migrates, the extension stores it as an `admin` key under a tenant with the slug `operator`. It does this once: a later start finds the key by its hash and changes nothing. Surrounding whitespace in the value is trimmed, so a trailing newline from a secrets file is fine. A revoked bootstrap key stays revoked and is logged as a warning with its id, and so is one that exists without the `admin` scope or under another tenant. A value of the wrong shape stops the start with an error that names where it came from and how long it was. If you set `disable_migrate`, the key is still created, so migrate the store yourself first.

The value is a secret. The extension never logs it or puts it in an error, but a YAML file under source control keeps it forever, so prefer the environment variable. See [Your first admin key](/docs/api-reference/http-api#your-first-admin-key).

### Requiring file config

If your deployment relies on the config file being present, use `WithRequireConfig`:

```go
ext := nexusext.New(
    nexusext.WithRequireConfig(true),
)
```

When `RequireConfig` is true and neither key exists, `Register` returns an error.

## Extension options

| Option | Purpose |
|--------|---------|
| `WithProvider(p)` | Register an LLM provider |
| `WithDatabase(s)` | Set the store. A store built from a `grove.DB` replaces it, see below |
| `WithGroveDatabase(name)` | Resolve a named `*grove.DB` from DI (empty name: the default one) and build the store from it |
| `WithGatewayOption(opt)` | Pass any `nexus.Option` to the gateway |
| `WithStreamCache(sc, opts)` | Stream record-and-replay caching, same as `nexus.WithStreamCache` |
| `WithStreamLifecycleConfig(cfg)` | Tune stream hook fan-out and per-tenant stream caps |
| `WithConfig(cfg)` | Set the extension config in code |
| `WithRequireConfig(bool)` | Fail `Register` when the config key is missing |
| `WithDisableMigrate()` | Skip the store migration on start |
| `WithBasePath(path)` | Accepted, has no effect |
| `WithDisableRoutes()` | Accepted, has no effect |

## Grove database integration

When your Forge app uses the [Grove extension](https://github.com/xraph/grove) to manage database connections, Nexus builds its store from a `grove.DB` in the container. It picks the backend from the driver name: `pg` gives the PostgreSQL store, `sqlite` the SQLite store and `mongo` the MongoDB store. Any other driver fails `Register`.

### The default grove database

If a default `*grove.DB` is in the container, the extension uses it without any option. Calling `WithGroveDatabase("")` does the same, but turns a missing database into a `Register` error instead of a silent fallback to memory.

### A named grove database

In multi-database setups, name the one Nexus should use:

```go
ext := nexusext.New(
    nexusext.WithGroveDatabase("nexus"),
    nexusext.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))),
)
```

Or in YAML:

```yaml
extensions:
  nexus:
    grove_database: "nexus"
```

`Register` fails if no database by that name is in the container.

### Store resolution order

1. With `WithGroveDatabase` or `grove_database` set, the named (or default) `grove.DB` is resolved, and `Register` fails if it's missing.
2. Otherwise, if a default `grove.DB` is in the container, it's used.
3. Otherwise the store you passed with `WithDatabase`, if any.
4. Otherwise the gateway's in-memory store.

A store built from Grove in step 1 or 2 replaces one you passed with `WithDatabase`. To use your own store in an app that has a default `grove.DB`, there's no option for that today.
